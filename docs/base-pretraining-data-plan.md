# 基础预训练数据规划 v0.1

> 状态：规划与候选来源审计；尚未批准任何数据源，也尚未开始全量下载。
>
> 范围：从头训练共享基础语言模型。此阶段不训练记忆选择器，不使用未来效用标签，也不把 Phase 0 的合成关系链当作主要预训练语料。

## 1. 目标与实验边界

先让模型学会中英文阅读、技术文本、简单代码和基础数学，再训练指令与工具使用，最后比较长期记忆结构。基础预训练使用因果语言建模：给定前缀，预测下一个 token。基础模型合格后保存同一个 checkpoint，供后续 A/B/C 架构实验共享。

训练前必须冻结分词器版本、模型配置、语料版本、采样顺序和独立验证集。20M–50M 模型只用于数据与训练管线验收；100M–150M 的受控比较和最终约 1B 训练所需 token 数，在 L40 吞吐实测和数据审计后确定，不先凭经验填数。

## 2. 数据分层

| 层次 | 内容 | 本阶段用途 |
|---|---|---|
| 通用文本 | 中英文高质量说明、知识与教育文本 | 阅读、表达、基础常识 |
| 技术文档 | API、编程语言、工具使用说明及实例 | 理解开发语境与命令 |
| 代码 | 以 Python、Shell 为主的可归属来源代码和测试 | 语法、局部补全、简单程序结构 |
| 数学 | 基础到中等难度的教材式解释、例题与解法 | 数学语言、符号和基本步骤 |

这四层是**来源桶**，不是互斥的能力标签。一个网页可能同时包含数学和代码；入库时指定主来源桶，并在全库去重，避免同一文本被多次采样。指令微调、工具调用轨迹和长期记忆任务另建数据集与配方，不在这一轮混入基础预训练的质量统计。

## 3. 首轮候选来源，不等于批准使用

可机读的初始候选与 Hub 版本快照见 [base-data-sources-v0.yaml](base-data-sources-v0.yaml)；其中的版本只是观察值，正式抽样前还需锁定子集并复核许可。

| 来源 | 候选桶 | 当前待查问题 |
|---|---|---|
| [FineWeb-Edu](https://huggingface.co/datasets/HuggingFaceFW/fineweb-edu) | 英文通用/教育文本 | 抽样质量、网页模板、与其他语料重复 |
| [CCI3-HQ](https://huggingface.co/datasets/BAAI/CCI3-HQ) | 中文通用文本 | 访问条件、实际内容质量、可用子集 |
| [The Stack v2](https://huggingface.co/datasets/bigcode/the-stack-v2) | Python/Shell 代码 | 原仓库逐项许可、归属信息、泄漏与重复 |
| [FineMath](https://huggingface.co/datasets/HuggingFaceTB/finemath) | 英文数学文本 | 难度是否适合小模型、答案质量、网页重复 |
| 官方技术文档与教学材料 | 技术文档 | 逐站点许可、版本、抓取与结构保留方式 |

代码数据不能只看集合级标签：The Stack v2 的数据卡要求遵守原仓库许可。CCI3-HQ 在 Hugging Face 上需要完成访问条件。任何来源未过审前，状态只能是 `candidate`。

## 4. 数据清单格式

清单放 Git，只保存元数据，不放大体积原文。每个来源至少记录：

```yaml
source_id: fineweb_edu_sample
url: https://huggingface.co/datasets/HuggingFaceFW/fineweb-edu
revision: null              # 审计通过后填写精确 commit/revision
subset: null
domain: general_en
language: en
license_review: pending
access: public
status: candidate           # candidate / sampled / approved / rejected
sample_seed: 20260923
sample_documents: 0
sample_bytes: 0
estimated_tokens: null     # 分词器冻结后填写
accepted_fraction: null
exact_duplicate_fraction: null
near_duplicate_fraction: null
pii_secret_hits: null
eval_overlap_hits: null
notes: null
```

每个处理后的文档保留 `document_id`、`source_id`、原始定位符、来源版本、内容哈希、语言、主领域、分割组和过滤原因。原文与清洗后文本分开放置；训练文件由清单和固定随机种子重建。

## 5. 审计到训练的工作流

1. **清单初建**：列出来源、访问与许可条件；候选不算可训练数据。
2. **分层抽样**：每个来源先取约 1,000–5,000 篇，覆盖不同长度、子集和时间；记录抽样种子，不直接下载全集。
3. **质量审查**：自动统计语言、长度、编码异常、模板/广告、重复、代码缩进和公式损坏；每来源人工抽看约 100 篇，标记可用、可修复或排除。
4. **污染与去重**：先按文档/仓库/题目族确定训练和验证的隔离单位，再做规范化哈希与近重复检查；对锁定的短任务评测集做重合检查。
5. **分词器试验**：用各来源代表性文本训练候选分词器，比较中英、Python/Shell、数学公式的 token/字节与可逆性；选定后记录文件哈希。
6. **清洗与打包**：保留代码缩进、换行和数学符号；每篇文档加结束标记，转为 token ID，按固定顺序打包训练块；保存来源分布和数据哈希。
7. **小模型验收**：先做单卡短跑，验证无 NaN、正确恢复 checkpoint、训练/验证集不串、各领域验证损失正常；再做 20M–50M 试跑。

清洗规则和采样权重都必须版本化。首轮不先冻结“四桶比例”：先得到可用 token、质量与分词统计，再为 20M–50M 试跑预注册一个混合比例，之后只根据独立验证集和能力评测调整。

## 6. 验收指标

- **数据**：可用文档数、可用 token 数、按来源/语言/领域分布、过滤比例、精确与近重复率、验证集重合数。
- **分词**：中英、代码、公式的 token/字节分布；常见代码片段和公式可逆恢复。
- **训练**：总训练 loss、按来源的验证 NLL 与 BPB、梯度/数值稳定性、数据加载吞吐、恢复后曲线连续性。
- **能力诊断**：短上下文中文/英文理解、简单代码补全、基础算术和符号格式。试跑失败只用来定位数据、分词器或模型问题，不直接宣称架构无效。

不同分词器的 perplexity 不直接比较；跨分词器报告 BPB。基础训练的成功门槛是**训练管线可靠、验证趋势可信、没有明显领域退化**，不是让 20M–50M 模型已经具有成熟 Agent 能力。

## 7. 存储与发布

- Git 仓库：来源清单、处理脚本、抽样/清洗配置、审计汇总、分词器和训练配置的版本信息；不提交原始语料、token 大文件或密钥。
- JFS：原始下载、清洗数据、token shard、训练 checkpoint 分区存储；每一层有版本与校验和，避免重复拷贝和杂乱目录。
- Hugging Face 模型仓库：将来发布关键 checkpoint、分词器、加载说明和模型卡；模型卡引用最终使用的来源版本与实际 token 统计。当前仓库为 [small-agent-1b](https://huggingface.co/wangyue114514/small-agent-1b)，还没有权重。
