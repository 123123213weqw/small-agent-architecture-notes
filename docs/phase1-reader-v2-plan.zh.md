# Phase 1 Reader v2：逐关训练与诊断计划

> 目的：先证明开源 Base 接入的可训练读取层能够使用旧记录。此阶段不训练效用预测器，不比较 FIFO/C，不修改记忆淘汰公式。

## 固定项

- 基座：`Qwen/Qwen3-0.6B-Base`，revision `da87bfb608c14b7cf20ba1ce41287e8de496c0cd`，原 tokenizer；所有关卡从同一基座出发。
- 旧记录是不可变的原始 token 序列。由冻结基座对**每条记录独立编码**为上下文化隐藏状态，Reader 用 Cross-Attention 读取；训练 Reader 投影，先不更新基座。
- 每题答案为 0–9 中一个随机数字，记录 ID 与数字按 episode 随机绑定；查询 prompt 不含答案。训练、验证按 episode 种子隔离。
- 读取层在初始时输出零增量，但不设置可被 LM loss 关到零的可训练全局门。训练可用已知的目标记录索引作辅助定位监督；该索引只存在于合成训练数据，不作为推理输入。

## 顺序与停止条件

| 关卡 | 训练数据和动作 | 对照与验收 | 失败定位 |
|---|---|---|---|
| 0. 基座可读性 | 旧记录直接写进普通上下文；不训练 | 旧记录可见时的准确率显著高于仅查询；前轮 8 记录已达 128/128 | 基座/题目格式 |
| 1. 单记录读取 | 每例 1 条 `ID→随机数字` 工具结果；训练读取层预测答案 | 未见 episode 准确率目标 ≥90%；正确记忆 NLL 低于错配记忆 | 旧记录编码、注入位置或梯度 |
| 2. 多记录定位 | 从关卡 1 adapter 接续，8 条记录中查询随机 1 条；增加按目标 slot 的辅助定位 loss | 未见 episode 准确率目标 ≥70%；正确/错配记忆有稳定 NLL 差；检查 slot 命中率 | 跨记录检索、干扰抑制 |
| 3. 延迟工具信息 | 旧目标记录离开近期窗口，加入更多非目标事件；Reader 暂时由训练数据提供保留证据 | 有证据与无证据、正确与错配记忆配对评估；另测新 ID/新模板 | 长程表示/泛化 |
| 4. 选择器 A/B/C | **只在关卡 1–3 的 Reader 可读后**从同一 checkpoint 分叉 KV、FIFO、效用淘汰 | 相同任务、相同状态预算，多种子评估 | 记忆选择 |

关卡 1/2 的阈值是首轮工程门槛，不是论文结论。每次保存输入生成种子、模型 revision、配置、adapter、逐步 loss、正确/错配记忆 NLL、答案准确率与目标 slot 注意力。只要关卡未过，就不把之后关卡的失败解释为效用数学失败。

## 梯度

Reader 训练先用 $L=L_{\mathrm{answer}}+\lambda L_{\mathrm{slot}}$。单记录时 $L_{\mathrm{slot}}=0$；多记录的 slot 标签来自合成数据生成器，仅帮助读头学会把查询与旧记录对齐。推理不输入 slot 标签。完整语言模型基座先冻结；如果单记录未学会，优先检查位置、LM head 几何和梯度，然后受控地解冻顶部层，而不是直接修改淘汰公式。

## 本轮执行结果（2026-09-23）

上述顺序中的 0、1、2、3 已执行单种子诊断。训练例子都是按 episode 随机生成的工具记录和数字答案，不是此前审核的 400 条文本。每个测试条件使用 256 个固定的未见 episode；这些任务仍很简单，不能替代真实 Agent 测评。

| 检查 | 训练或干预 | Reader 准确率 | 同题把记录直接放入基座上下文 |
|---|---|---:|---:|
| 单记录 | 上下文化记录编码，1000 步 × 16 | **100%** | 100% |
| 八记录，同写法 | 从单记录接续，2000 步 × 16；最终 checkpoint | **73.8%**（显式前缀输入复测；原训练日志 75.0%，过程最高 78.9%） | 100% |
| 八记录，四种格式混合 | 从八记录接续，3000 步 × 16；混合测试 | **58.6%** | — |

混合训练后的分项如下。训练混合包含：标准写法、四位 ID、另一种记录/问题写法、32 条近期干扰。`unseen_natural`、64 条干扰和五位 ID 没有进入训练混合。下表各项的基座全上下文准确率均为 **100%**。

| 256 题条件 | Reader 准确率 | 解释 |
|---|---:|---|
| 标准写法 | 86.7% | 同格式改善，但仍未到全上下文上界 |
| 四位 ID | 67.2% | 见过这个训练格式，仍有明显退化 |
| 改写记录和问题 | 10.9% | 近似十选一随机水平 |
| 32 条近期干扰 | 54.7% | 延迟环境明显退化 |
| **未见自然语言记录** | **9.8%** | 跨写法未泛化 |
| **64 条近期干扰** | **56.3%** | 对训练时 32 条有一定长度外推，仍不可靠 |
| **五位 ID** | **22.3%** | 实体格式外推弱 |

为分开定位记录写法与问题写法，做了单记录干预：删除所有竞争记录，只给真实目标记录。标准记录+改写问题为 **100%**；改写记录+标准问题仅 **20.3%**；两边都改写为 **11.3%**。这说明当前主要障碍**至少包含记录内容的编码/读出**，而不只是多 slot 淘汰或定位。注意平均注意力的 slot 命中率不是忠实因果解释，不能单靠它断言具体内部机制。

追踪实验：从同一个标准八记录 adapter 出发，**只训练“改写记录 + 标准问题”** 2000 步，其他配置不变。如果该条件明显学会，说明接口具备表示能力而混合训练存在优化/干扰问题；若仍不学，则优先调查记录表示和注入位置。该追踪实验不用于选择最终架构。

追踪结果：从标准八记录 adapter 直接切换到改写记录，2000 步后仍约 **9.8%**；但从零先训**单条改写记录**，1000 步达到 **98.4%**，再扩到八条记录、训 2000 步达到 **54.7%**。因此不能断言该接口在数学上无法表示改写格式；更准确的诊断是**格式切换与扩容的训练路径高度敏感**。下一项只改训练顺序：先在单记录阶段混合四种写法，再扩到八记录；模型参数和损失保持不变。这个顺序消融若仍失败，才更有理由改读取层设计。

还做了一个小消融：Cross-Attention 的 Key 保留基座上下文化状态，Value 改用原始 token embedding。单记录 1000 步仅 **54.3%**；再训练 2000 步（新种子）约 **71.5%**，没有达到上下文化 Value 在 1000 步的 100%。这只排除了“直接换 token embedding 就立刻解决”的简单猜想；未进行等收敛预算的最终架构比较。

**阶段结论：**新的 Reader 可以训练成功，但目前只在有限格式内有效。关卡 3 的跨写法门槛未通过，所以按预注册顺序**不启动 FIFO/效用选择器正式 A/B/C**。下一项应聚焦跨格式的记录表示与读取接口，而非修改效用淘汰公式。完整逐步指标及配对控制位于 `results/phase1_reader_v2/`；远程 adapter 和 TensorBoard 事件位于对应 `runs/phase1_reader_v2_*` 目录。

数据生成和标签不泄漏测试：`/opt/homebrew/bin/python3.11 -m unittest tests.test_phase1_reader_v2_data -v`，2 项通过。训练脚本为 `experiments/phase1_reader_v2.py`，分项配对评测脚本为 `experiments/phase1_reader_v2_variant_eval.py`。

## 下一轮：多卡训练顺序消融（执行中）

目标是只检验“先混合格式学会单记录，再增加记录数量”是否改善此前的格式切换失败。固定基座、Reader 数学结构、学习率和损失；不在本轮训练效用选择器。

1. **资源核查**：只使用确认空闲的 L40 GPU 3、4、7；其他 GPU 上的已有进程不动。每个 GPU 独立运行一个种子，避免数据并行同步及其额外变量。
2. **单记录多格式训练**：三个种子 `260923`、`260924`、`260925`，每个从同一冻结 Base 和新初始化 Reader 开始，`slots=1`、`steps=2000`、`batch=16`、学习率 `3e-4`。每个 episode 从标准、四位 ID、改写记录与问题、32 条近期干扰四种条件中抽一个；每 200 步用 256 条未见 episode 评估。
3. **统一配对测试**：训练完用相同的评估种子，逐项测标准、四位 ID、改写、延迟 32、未见自然语言、延迟 64、五位 ID；同时测把全部旧记录放入基座上下文的上界、以及错配记录的 NLL。平均混合准确率不能替代分项准确率。
4. **继续/停止闸门**：先检查各训练格式的单记录准确率和种子差异。若四种已见格式均基本学会（目标 ≥90%），才从每个单记录 adapter 扩到 8 记录；否则记录失败分项，优先定位格式编码、训练时长和优化，不进入八记录选择器比较。
5. **八记录扩容**：沿用各自种子的单记录 adapter，保持训练混合与其他参数，`slots=8`、`steps=3000`、`batch=16`，加入 `0.5 L_slot` 辅助项；完成后做第 3 步同样的逐项配对测试。与此前“标准单记录→标准八记录→混合八记录”的顺序比较；报告三种子均值、范围和每个分项，不只报最好的一次。
6. **结论边界**：只有跨格式读取稳定后，才从同一个 Reader checkpoint 分叉 KV/FIFO/效用淘汰的正式 A/B/C；这轮合成数字任务不能证明真实 Agent 能力或淘汰公式优越性。

### 多卡单记录结果

三个独立初始化的种子在 L40 GPU 3、4、7 同时训练，各自 2000 步。以下分项统一使用另一个评估种子 `981733`、每项 256 题；表内为准确率。全上下文 Base 在这些条件约 100%。

| 单记录训练种子 | 混合验证（各自种子） | 标准 | 四位 ID | 改写记录与问题 | 延迟 32 | 未见自然记录 |
|---|---:|---:|---:|---:|---:|---:|
| 260923 | 66.0% | 87.9% | 88.3% | **10.2%** | 84.0% | 13.7% |
| 260924 | **100%** | **100%** | **100%** | **100%** | **100%** | 23.4% |
| 260925 | 80.5% | 100% | 100% | **9.4%** | 100% | 10.5% |

该训练顺序在 1/3 种子上学会所有已见格式，但不稳定；即使最好的种子也没有泛化到未见自然语言记录。混合指标会掩盖“改写格式”接近随机水平，不得单独作为过关依据。三个种子的正确记忆 NLL 均低于错配记忆，因此“总体会用记忆”也不意味着每种记录写法都学会。

**探索性追加训练，不计入原 2000 步比较：**把失败种子各自的 adapter 接续训练 2000 步，使用新 episode 种子并重新初始化 AdamW。种子 260923 的改写分项回升到 **82.0%**，但标准/四位 ID 约 85%；种子 260925 的改写仍只有 **13.7%**。这说明至少一部分失败可被额外训练缓解，但仍不能保证稳定收敛，也不是等同于原训练继续 2000 步的严格对照。

### 八记录扩容结果

按上述闸门，仅从四种已见格式均达 100% 的单记录种子 260924 出发，扩至 8 记录，混合格式训练 3000 步。最终混合准确率 **10.5%**，目标槽平均注意力最大项命中率 **13.3%**（八选一随机基线 12.5%），正确/错配记忆 NLL 差仅 **0.30**。统一评估种子上的七种格式均约 11–16%，而全上下文 Base 为 **99.2–100%**。因此预定的八记录门槛未过，不能继续进行 FIFO/效用淘汰正式比较。

为分辨失败位置做了以下**事后诊断**，均为 8 槽、`batch=16`、相同学习率。前两行使用相同的八记录训练种子 `260924` 和标准格式；单记录前置 checkpoint 的初始化种子不同，因此不是只改变一个因子的严格因果比较。

| 八记录训练路径 | 步数 | 最终答案准确率 | 目标槽注意力最大项命中率 | 错配 NLL − 正确 NLL |
|---|---:|---:|---:|---:|
| **标准单记录 → 标准八记录** | 2000 | **80.5%** | 78.9% | +4.02 |
| **混合单记录 → 标准八记录** | 2000 | **12.5%** | 83.6% | +0.50 |
| **混合单记录 → 混合八记录** | 3000 | **10.5%** | 13.3% | +0.30 |
| **从头直接训混合八记录** | 3000 | **11.7%** | 25.8% | −0.02 |

前两行说明：即便路由指标相近，答案读出也可相差很大。slot 辅助目标能改变平均注意力的路由指标，却不保证答案成功；此指标并非忠实因果归因，不能直接解释为真正读取正确记录。直接从头训练混合八记录也没有越过随机水平。此前“标准单记录 → 标准八记录”本来就能做到约 74–80%，因此目前问题更像**多格式与多记录同时组合时的优化/接口相容性**，而非当前模型完全不具备多记录能力。

**下一步应是小规模机制排查，不是立刻训练 1B 或改记忆淘汰公式。**建议固定标准单记录 checkpoint，逐个加入“新记录写法”“新查询写法”“多记录干扰”，比较每项的梯度、输出贡献和答案准确率；随后尝试显式的两阶段读取（先选记录，再读记录内值）或轻量可训练记录编码器。任何新接口都从相同 Base 与相同样本预算重新比较，不能把当前事后最佳结果当正式胜利。正式 FIFO/C A/B/C 仍暂停。
