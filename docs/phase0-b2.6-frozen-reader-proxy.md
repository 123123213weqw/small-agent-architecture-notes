# Phase 0 B2.6：冻结 Reader 的记忆筛选代理实验

## 要回答的问题

在真正训练 1B 混合模型之前，先检查：当旧信息离开短窗口后，以相同的输入记录数进行筛选，是否能让一个已有语言模型完成延迟关系查询？这只验证**信息选择与 Reader 读取的组合**，不能证明我们的效用预测器已经学会筛选，也不等于测量真实 KV cache 的速度或显存。

## 冻结条件

- Reader：`Qwen/Qwen2.5-1.5B-Instruct`，参数冻结，贪心生成，不微调。
- 每个 episode 128 条有向映射；最后 16 条作为短窗口。早期记录中藏有 2 跳或 4 跳唯一链。其他映射完全不接触链上的节点。
- 长期记忆容量 12 条；除 `full_context` 外，Reader 均看到 12 条旧记录加最后 16 条记录，共 28 条。所有记录采用相同格式，实测 tokenizer 输入 token 数应一致。
- 问题给出链起点和跳数，从四个随机排列的节点选项中作答。目标节点是每个 episode 随机生成的、不靠语言常识可猜。相同 episode 在各策略中复用。
- `recency`：保留最近 12 条过期记录；在本静态 prompt 代理里，这与总共看最近 28 条的“等预算 KV-only”**信息集合完全相同**，不应伪称为独立胜负。
- `lexical`：在线优先保留与目标起点字面相交的旧边；其余按最近优先。
- `graph`：在线维护从目标起点可达的边，优先保留源点当前可达的边。它读取结构化端点，是可行性参照，**不是当前字节编码效用模型**。
- `oracle`：事后挑出真实链边，再用最近旧边填满容量；只作信息上界，不能在线部署。
- `full_context`：不筛选，提供全部 128 条记录；这是**约 4.6 倍证据长度的非等预算参照**，用于检验普通全上下文 Transformer 能否解题。

## 判据与解释边界

先看 `oracle`：若它都明显失败，不能把其他策略的失败归因于记忆选择，需改 Reader、提示或任务。若 `graph` 明显好于 `recency`，说明短窗口之外的有用证据可以通过在线结构选择恢复；但成功很可能来自合成数据里极干净的图连通性。`lexical` 的表现检查单词重叠是否足够。`full_context` 如果同样成功，则说明完整上下文注意力可以解决该题；记忆的潜在价值是以较小上下文预算接近它，而不是“全注意力没有能力”。

该实验不测真实增量 KV、吞吐、延迟、token/byte 级缓存预算，也不测可学习效用预测器；不能由此宣称数学结构优于 Transformer 或线性注意力。后续需要将当前 `f_φ` 接入同一 Reader 评测，并在训练出混合模型后做相同算力/显存预算的端到端对照。

实现：`experiments/phase0_b26_reader_proxy.py`。结果：`results/phase0_b26/`。

## 实测结果（2026-09-23）

使用 L40 的一张卡，固定随机种子 2600；每种跳数 64 个 episode，每个 episode 由五种策略使用同一个 Reader 贪心回答。`main.json` 保存逐题预测、正确性、证据完整性和 token 数。四个等预算条件均为 **520 input tokens**；`full_context` 为 **2049 input tokens**，没有截断。

| 跳数 | 最近窗口/FIFO | 字面规则 | 在线图规则 | 未来 Oracle | 全部 128 条 |
|---|---:|---:|---:|---:|---:|
| 2 跳，准确率 | 12/64 = 18.8% | 12/64 = 18.8% | **52/64 = 81.2%** | 52/64 = 81.2% | 42/64 = 65.6% |
| 4 跳，准确率 | 16/64 = 25.0% | 17/64 = 26.6% | **55/64 = 85.9%** | 55/64 = 85.9% | 20/64 = 31.2% |

对应证据完整率：最近窗口/FIFO 在两档均为 0%；字面规则在 2 跳为 5/64，4 跳为 0%；在线图规则、Oracle、全上下文均为 64/64。四选一的无证据参考准确率约 25%。全部回答都解析成 A/B/C/D，没有无效输出。

在线图规则与 Oracle 在本次全部 128 个 episode 中选择了**完全相同的 12 条旧记录**，所以两列的相同准确率不是两个独立证据。这是因为数据生成器让干扰边与真正链完全断开、且真实边按链顺序到达；已知起点的图可达性足以在线找齐整条链。这个成功**不能外推到 spoke 干扰、未来才连通的链、自然语言工具结果或未知目标**。

以相同 episode 作配对比较，在线图规则相对最近窗口提高 62.5 个百分点（2 跳）和 60.9 个百分点（4 跳）；按 episode 重采样的 95% bootstrap 区间分别为约 `[50.0, 73.4]` 和 `[48.4, 73.4]` 个百分点。这只描述当前合成分布的抽样不确定性，不包含跨任务泛化误差。

全上下文已经拥有全部正确证据，却在 4 跳只有 31.2%；这表明当前冻结的 1.5B Reader 在大量相似干扰记录中并不稳定。不能说“Transformer 数学做不到”：这里没有训练、更大模型对照或认真优化全上下文提示。也不能把本次 520 对 2049 token 的输入差异直接换算为真实 KV 显存或速度优势。

## 本轮结论

这个代理任务通过了最低门槛：**一旦有因果可行的选择器把必要旧记录放进有限记忆，冻结 Reader 能利用它**；单纯扩到最近 28 条不能恢复早期链。它没有证明我们现有的 `f_φ` 能实现这种选择，更没有证明最终新架构优于同预算训练的 Transformer。下一项最有鉴别力的实验是把 B2.4 的已训练效用预测器也接进同一 Reader，对照上述在线图规则；随后引入 `spoke` 和乱序到达，防止当前清洁图结构带来的乐观偏差。
