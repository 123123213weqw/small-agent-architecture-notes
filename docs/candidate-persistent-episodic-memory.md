# 早期持久情景记忆推导（已归档）

> 状态：Superseded。本文只记录被放弃的设计路径，不再作为实现规范。当前规范见 [效用巩固记忆 v1](utility-consolidation-memory-v1.md)。

## 1. 早期方案

早期方案试图同时加入：

- 学习式事件边界；
- 新奇度和 surprise；
- soft slot routing；
- 显著性、年龄和 occupancy；
- 指数衰减；
- 冲突检测；
- 事件关联图；
- 原始片段二阶段回看。

该方案被放弃，不是因为每个组件都必然无效，而是因为组件过多、训练归因困难，并且多个公式存在相互耦合的失败模式。

## 2. 已确认的主要问题

### 2.1 Soft write 的槽坍缩

若所有槽初始化相同，则：

\[
p_i^{\mathrm{match}}=p_i^{\mathrm{replace}}=\frac1S,
\]

从而：

\[
\omega_i=\frac{g_e^w}{S}.
\]

所有槽得到相同更新，槽相等状态成为更新方程的不变子空间。经过 \(E\) 次均匀写入，occupancy 可能显示：

\[
o_i^{(E)}=1-\left(1-\frac1S\right)^E,
\]

但所有槽内容仍可能完全相同。因此 occupancy 不能证明系统形成了不同记忆。

### 2.2 立即判断重要性的因果限制

两个任务可以在事件出现前具有相同历史，但在未来一个需要该事件、另一个不需要。任何只依赖当前历史的函数都无法知道唯一未来，只能预测训练分布下的期望效用。

### 2.3 过去用途不等于未来保留价值

事件在等待期内频繁使用，不代表决策之后仍有价值；等待期内没有使用，也不代表任务末尾不会需要。因此训练标签必须评估巩固决策之后的未来，而不是事件出现后的等待区间。

### 2.4 过度设计

早期方案把写入、遗忘、冲突、关联、替换和回看分别设计成独立模块，造成：

- 超参数和初始化规则过多；
- 联合优化目标不清晰；
- 难以确定收益来源；
- 小模型容量被控制器消耗；
- 训练与推理行为容易不一致。

## 3. 当前版本保留的思想

当前 v1 只保留以下研究动机：

1. 长期状态必须有界；
2. 记忆记录必须能被独立识别和移除；
3. 记忆价值应由决策后的未来任务损失定义；
4. 推理时预测期望删除成本；
5. 任何新增复杂性必须在最小原型失败后再提出。
