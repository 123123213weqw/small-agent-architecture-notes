# Base-1B-v1 架构冻结

日期：2026-09-24。配置源文件：`configs/gdn/base_1b_v1.json`。

## 决定

从随机初始化训练文本专用、Dense、因果语言模型。使用已冻结的 Byte-level BPE 32k `tokenizer_v1`；不加载现成模型权重。以已在 45M 工程短跑中测试的 Qwen3Next GDN/GQA 实现作为首版代码基础，但本项目使用自己的尺寸、分词器、语料和权重。

| 项目 | Base-1B-v1 |
| --- | --- |
| 层数与排列 | 32 层，`[GDN, GDN, GDN, GQA] × 8`；24 个 GDN、8 个全局因果 GQA |
| 模型宽度 | 1536 |
| Dense SwiGLU FFN 宽度 | 4096 |
| GQA | Q 头 16、KV 头 4、每头 96 维；全局注意力使用 RoPE |
| GDN | key/value 头均 16、每头 96 维；局部卷积核 4 |
| 词表与输出 | 32768；输入 embedding 与输出 LM head 权重共享 |
| 归一化 | 使用该实现的 RMSNorm / GDN gated norm |
| 位置范围 | 配置上限 8192；第一阶段先以 4096 训练，8192 扩展作为单独阶段 |
| 精度 | 权重初始化按 FP32，训练计算 BF16；数值实现以锁定环境的实测为准 |

不使用 MoE、视觉塔、旧效用记忆选择器或外接 Reader。Agent 工具格式、代码与数学能力属于后续数据和训练阶段，不通过额外主干模块实现。

## 参数量口径

在 L40 的 PyTorch 2.5.1 / Transformers 4.57.1 环境中，以该 JSON 构造 `Qwen3NextConfig`，在 meta 设备实例化 `Qwen3NextForCausalLM` 后，使用 `sum(p.numel() for p in model.parameters())` 得到**准确参数量 1,005,213,696**（约 10.05 亿）。核对了 24 个 GDN、8 个 GQA，且输入 embedding 与输出 head 确实共享同一权重。这是结构参数计数，不代表目标尺寸已通过 GPU 训练验收。

## 冻结边界与启动门槛

本文件冻结的是**第一版要训练的结构**，不是“GDN 优于 Transformer”的结论。不得因为小型验证集短期波动改变层序、头数或宽度。只有实例化失败、数值异常、显存/吞吐无法满足预算等工程性阻断，才提出带版本号的修改。

正式长跑前仍须：① 用目标尺寸在 L40 上验收实际 GPU 前反向、4096 上下文、优化器与分布式恢复；② 冻结训练许可通过的大规模语料及独立验证集；③ 固定训练 token 预算、采样配比与评测。现有约 114 万 token 只用于工程冒烟，不是 1B 正式预训练数据。
