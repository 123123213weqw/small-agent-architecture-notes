# Phase 0B2：从文本预测记忆效用

## 1. 问题

Phase 0B 的结构化 MLP 可以直接读取 `consumed`、`unresolved`、目标匹配和关系连通等字段。它验证了效用信号存在，但没有验证模型能否从原始事件文本中抽取这些信号。

Phase 0B2 删除这些人工输入，只提供决策时已经可见的文本：当前任务目标、一条待评分候选记录、最近两条已观察事件，以及当前竞争集合的有界文本视图。未来事件只用于生成反事实监督标签，绝不进入预测器输入。

## 2. 模型

第一轮使用从零训练的字节级 Transformer Encoder：

| 项目 | 配置 |
|---|---:|
| 参数量 | 4,969,473 |
| 层数 | 6 |
| 隐藏维度 | 256 |
| 注意力头 | 8 |
| FFN 维度 | 1024 |
| 最大输入 | 384 bytes |
| 训练 episode | 1,200 |
| 训练样本 | 45,743 |
| 训练轮数 | 6 |

模型通过加权 MSE 直接回归反事实效用，并根据预测值淘汰最低分记录。

## 3. 防止词面匹配直接解题

每个 episode 加入最多 14 条 hard negatives。它们与任务目标共享相同标识符，但文本语义表明记录已经消费、已经结束、已经过期，或者只是无法组成正确路径的关系边。

因此，精确关键词匹配只能完成候选召回，不能可靠完成最终淘汰。实验另外报告不使用语义的标识符重叠基线 `Lexical`。

## 4. 三个测试分布

- `id`：新实体和新事件流，但使用训练期表达模板；
- `paraphrase`：长度相同，记录和目标全部换成训练中未出现的释义模板；
- `ood_length_paraphrase`：同时采用新释义，并把长度从训练期的 32–64 扩展到 96–128。

通过条件同时要求：恢复至少 50% 的 Oracle−FIFO 差距，并且成功率至少比 Lexical 高 5 个百分点。

## 5. Seed 0 第一轮结果

| Split | FIFO | Lexical | Text | Structured baseline | Oracle | 恢复比例 | 结论 |
|---|---:|---:|---:|---:|---:|---:|:---:|
| `id` | 0.100 | 0.483 | 0.992 | 0.958 | 1.000 | 99.1% | PASS |
| `paraphrase` | 0.125 | 0.475 | 0.333 | 0.933 | 1.000 | 23.8% | FAIL |
| `ood_length_paraphrase` | 0.033 | 0.458 | 0.333 | 0.908 | 1.000 | 31.0% | FAIL |

## 6. 结论

当前模型能学习训练模板内的文本淘汰规则，但没有学到可迁移的语义。它在同模板测试上几乎达到 Oracle，却在未见释义上低于简单 Lexical 基线。因此 **Phase 0B2 尚未通过，不能进入 20M–50M Reader 阶段**。

这不是效用公式本身失败：Structured baseline 在两个释义测试上仍分别达到 0.933 和 0.908。失败点位于从文本到结构化效用线索的表示学习。

## 7. 实验结构审计

第一轮适合作为管线诊断，但还不能作为最终 B2 结论，原因如下。

### 7.1 做对的部分

1. 未来记录只参与标签生成，不进入预测器输入；
2. 所有淘汰策略使用相同容量；
3. 评估执行真实的连续淘汰 rollout，而不是只报告离线分类准确率；
4. hard negatives 让目标标识符重叠不再等价于正确答案；
5. 同时提供 FIFO、Random、Lexical、Structured、Text 和 Oracle；
6. 分开测试模板内、释义外和长度外推。

### 7.2 当前混杂因素

1. **ID 测试可以记模板。** 训练和 ID 测试共享固定句式，0.992 更接近模板规则学习，而非开放文本理解。
2. **释义测试过于突然。** 字节级模型只看过约 4.6 万条合成监督样本，没有语言模型预训练，却被要求理解训练中从未出现的同义表达；这个测试把“效用学习”和“语言知识”混在了一起。
3. **验证集按样本切分。** 同一 episode 的不同决策状态可能同时出现在训练集和验证集，验证 MSE 偏乐观。正式实验必须按 episode 切分。
4. **文本模型没有看到完整竞争集合。** 当前只放入最早两条和最近两条竞争记录，而且 384-byte 截断可能继续删除尾部；Structured baseline 却读取完整集合，两者信息预算并不相同。
5. **中文按 UTF-8 byte 截断。** 384 bytes 通常只有约 128 个汉字，实际上下文比表面配置短，必须报告截断率。
6. **缺少显式时间元数据。** 事件顺序是冻结设计允许的输入，但当前文本模型没有稳定 event index 或相对年龄，状态覆盖任务可能存在不可辨识情况。
7. **点式 MSE 与淘汰目标不一致。** 推理只关心竞争集合内的相对排序，当前损失没有直接训练最低效用记录的排序。
8. **Structured 不是 ceiling。** 它只是读取人工特征的基线；真正上界只有 Future Oracle。ID 上 Text 高于 Structured 并不矛盾。
9. **hard negative 生成依赖真值。** 这适合受控合成实验，但可能产生固定的正负模板痕迹，必须通过消融确认模型没有只识别记录类型。
10. **只有一个随机种子。** 当前结果只能用于定位失败模式，不能用于冻结结论。

## 8. 建议的 B2.1 结构

### 8.1 联合打分而不是逐条重复编码

将输入组织为：

$$
\left(g_t,B_t,m_1,\ldots,m_{S+1}\right)
\longrightarrow
\left(\hat u_{t,1},\ldots,\hat u_{t,S+1}\right).
$$

每条记录先独立编码，再由小型 Set Transformer 或 Cross-Attention 读取完整竞争集合。这样可以：

- 一次前向同时得到全部效用；
- 保留完整集合而不重复编码目标；
- 正确表达覆盖、冲突和关系组合；
- 直接训练集合内排序。

每条记录同时携带允许公开的 event index、相对年龄和候选标记，但不携带 `consumed`、`unresolved` 或真值相关字段。

### 8.2 分离三个泛化问题

1. **实例泛化**：新实体、新数值、新事件顺序，词汇和模板可见；
2. **组合泛化**：词汇均在训练中出现，但句式组合和任务组合未见；
3. **语言泛化**：使用训练中未出现的同义词和表达，需要语言建模知识。

B2.1 的硬通过线应以组合泛化为主。完全未见同义词作为压力测试；只有加入语言建模预训练后，才把它升级为阻塞条件。

### 8.3 损失

保留效用回归，同时加入集合内排序：

$$
\mathcal L
=
\mathcal L_{\mathrm{MSE}}
+
\lambda
\sum_{u_i\gt u_j}
\max\left(0,\delta-\hat u_i+\hat u_j\right).
$$

还应直接报告最低效用选择准确率、淘汰 regret 和最终任务成功率，而不是只看 MSE。

### 8.4 数据和基线

- 训练集、验证集和测试集按 episode 隔离；
- 每种语义使用多个模板族，完整留出一个模板族；
- 增加“同词面、相反语义”和“不同词面、相同语义”的成对样本；
- 增加 TF-IDF/字符 n-gram 线性模型，判断 Transformer 是否真正提供额外能力；
- 将 `Structured ceiling` 重命名为 `Structured baseline`；
- 按任务、容量、长度和 hard-negative 类型分层报告结果；
- 至少运行三个随机种子。

### 8.5 B2.1 通过条件

建议要求三个随机种子的组合泛化测试同时满足：

1. Text 恢复至少 50% 的 Oracle−FIFO 差距；
2. Text 至少超过最佳非神经文本基线 5 个百分点；
3. 六类任务中至少四类超过 FIFO；
4. 完整集合输入相对局部集合输入确实降低淘汰 regret；
5. 结果不能只由某个固定模板或记录类型贡献。
