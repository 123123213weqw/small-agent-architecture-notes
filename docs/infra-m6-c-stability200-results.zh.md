# M6：C 配置 200 步稳定性实验

日期：2026-09-24  
阶段：1B 工程稳定性测试，不是模型能力评测

## 1. 配置

延续 M5 的 C 配置：

- 8 张 L40；
- 4096 token 上下文；
- 单卡 microbatch 1；
- 梯度累积 4；
- 全局每步 32 个序列，即 131,040 个预测 token；
- 关闭 activation checkpointing；
- BF16 DDP 通信；
- 25 MiB DDP bucket；
- 每 25 步验证一次；
- 总计 200 个优化器步骤。

本轮没有保存模型 checkpoint，目的是先验证 C 配置持续运行时的吞吐、显存和数值稳定性。

## 2. 结果

训练完整跑完：

```text
steps                 200 / 200
predicted tokens      26,208,000
median throughput     49,698 token/s（第 4～200 步）
mean throughput       49,762 token/s（第 4～200 步）
peak allocated        34.99 GiB
peak reserved         36.75 GiB
non-finite loss       0
non-finite grad norm  0
```

分段吞吐如下：

| 步数 | 中位吞吐（token/s） |
|---|---:|
| 4～25 | 50,572 |
| 26～50 | 50,247 |
| 51～100 | 49,808 |
| 101～150 | 49,612 |
| 151～200 | 49,520 |

后半段相对最初稳定段下降约 2%，但没有突降、显存增长或数值异常。峰值显存预热后保持在 34.99 GiB，说明 C 不是只能通过十几步的临界配置。

## 3. Loss 应如何解释

验证 loss：

| 步数 | 验证 loss |
|---|---:|
| 0 | 10.723 |
| 25 | **7.589** |
| 50 | 7.878 |
| 75 | 8.059 |
| 100 | 8.051 |
| 125 | 8.084 |
| 150 | 8.185 |
| 175 | 8.244 |
| 200 | 8.265 |

训练 loss 从 10.70 降到 0.055，但这不代表模型已经学会通用能力。当前冒烟训练集只有约 111 万 token，本次重复了约 24 个 epoch。验证 loss 在第 25 步后回升，正是小数据反复训练导致过拟合的表现。

因此本实验只证明：

1. C 配置能在 8 张 L40 上连续运行 200 步；
2. 约 35 GiB 的峰值已分配显存稳定，没有随步数增长；
3. 约 49.7k token/s 的长期吞吐可以维持；
4. loss 与梯度始终为有限值。

它不证明 1B 模型的最终能力，也不能用这个小验证集决定正式预训练的最优停止点。

## 4. 后续

C 可以升级为当前性能默认配置。正式预训练前还需完成：

1. 8 卡 checkpoint 保存、恢复和数据游标一致性；
2. 使用更大的不重复语料做固定 token 训练；
3. 将验证集扩大到足以判断泛化，而不仅是检查程序能否运行。
